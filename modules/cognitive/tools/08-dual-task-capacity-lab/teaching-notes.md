# Teaching notes - Dual-Task and Limited Capacity Laboratory

`modules/cognitive/tools/08-dual-task-capacity-lab/`

**What it teaches.** A dual-task cost is a difference from your own
single-task baseline, not an absolute number, and it is usually
asymmetric: one task is protected at the other's expense. Comparing a
version where the second task needs an answer on every item against a
version where it only needs a count at the end separates a
shared-capacity account from a response-selection bottleneck.

**Before students start.** The combined block always runs last, so any
cost is measured against a less-practised baseline, which the tool has
no way to correct for.

**What students do.**
1. Predict what adding a second task will do to the first: slower, less
   accurate, both, or neither.
2. Choose the number task's difficulty and whether it needs an answer
   on every item or just a count at the end.
3. Run the letters-alone block, then the numbers-alone block, then both
   together.
4. Compare each task's cost against its own single-task baseline.
5. Run a second set with different settings, then sort five findings in
   the capacity-versus-bottleneck challenge.

**What to look for.** In the worked example, the letter task's cost is
much smaller than the number task's, an asymmetric cost rather than a
shared one. The counting-mode setting is the more diagnostic
manipulation: it isolates the response-selection step rather than
merely repeating the finding that both tasks got worse.

**Debrief.** Why does the tool refuse to run the combined block first?
In the counting version the number still has to be read and held in
mind; why did the letter task suffer far less there than in the
respond-every-item version? If a time cost shrank but errors grew, did
the cost actually shrink?

**Common misconception / caution.** Watch for "both tasks got worse, so
it must be one shared pool." A bottleneck account predicts exactly the
same pattern, so this alone settles nothing. Block order is fixed and
confounded, the combined block always follows the other two, so treat
any single block's cost as suggestive rather than clean.

**Use in class / timing.** A demonstration with the worked example runs
5 minutes. One set of three blocks takes 8 to 10 minutes. With a second
set, the challenge and debrief, about 30 minutes.
